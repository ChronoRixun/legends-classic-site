Steam Deck and Linux guide

Run the Ultimate Legends launcher through Proton, build X-Men Legends from your own copies of the games, and play it on your Deck.

Ultimate Legends, the Legends Classic builder and the XML2 Fix are Windows programs. Under Proton they are a compatibility path, not a native Linux release. This guide sticks to what a Steam Deck tester and our own Proton test PC have actually done, and it says so when something has not been checked yet.

You need both games: a disc image (.iso or XISO) of your own X-Men Legends disc for the original Xbox, and your own X-Men Legends II for PC, installed.

The build needs about 8 GB free, plus about 3 GB if you keep the build cache. Leave room for the X-Men Legends II folder and the disc image as well. Making the image: dumping guide. Already play XML1-recomp? On the Beta channel the launcher can also build from that extracted folder (not tried under Proton yet).

Current versions. Stable: launcher 0.4.0, Legends Classic 0.4.0, XML2 Fix 1.8.2. Beta: launcher 0.5.0-beta.4, Legends Classic 0.6.0-beta.1, XML2 Fix 1.11.0-beta.1. Both fixes include the Proton black-screen fix. Only the Beta launcher has drop-down lists that open under Proton.

What was tested

A Steam Deck, GE-Proton11-7

In October a tester set up and built X-Men Legends on a Steam Deck with the launcher (from launcher 0.2.1 on), then played the early campaign through the 0.1.8 to 0.2.2 builds.

In November the same Deck hit two Proton problems: the channel list would not open, and the game stayed on a black screen. The releases above fix both. The tester has not re-checked those fixes on the Deck yet.

Our Proton test PC

Linux in WSL on Windows, GE-Proton11-7 and later GE-Proton11-11, software graphics. We tested launcher 0.4.0 to 0.5.0-beta.4, switching channels both ways with in-place updates, builds and rebuilds, and the new drop-down lists of 0.5.0-beta.3 and later.

X-Men Legends 0.4.0 reached its main menu with XML2 Fix 1.8.2 and no extra settings. With 1.11.0-beta.1, X-Men Legends II started without the black screen, and a 0.6 beta build finished there. That build was not played.

Not tested yet open

Valve's own Proton releases. Gaming Mode on our side. A real controller under Proton. Games kept on an SD card. Building from an extracted XML1-recomp folder. Online play from a Deck. If you try any of these, tell us how it went (see Getting help).

1. Install the launcher (Desktop Mode)

Do the setup in Desktop Mode (Steam button > Power > Switch to Desktop). After that you can play from Gaming Mode.

  1. Install GE-Proton

    The tester used GE-Proton11-7 on the Deck. Our test PC ran GE-Proton11-7 and GE-Proton11-11. One way to install it: get ProtonUp-Qt from the Discover store, add GE-Proton with it, then restart Steam. Valve's own Proton has not been tried.

  2. Download the launcher

    From the Ultimate Legends releases, download ultimate-legends-<version>-win64-portable.zip and SHA256SUMS.txt. For Stable, take the release marked Latest. For the Beta, take the newest Pre-release (0.5.0-beta.3 or later is easier under Proton: see step 3). To check the download, run sha256sum on the zip in Konsole and compare the result with SHA256SUMS.txt.

  3. Unzip it where it can stay

    For example, /home/deck/Games/UltimateLegends. The launcher is portable: its settings, the builder it downloads and its own updates all live in the ultimate-legends folder next to ultimate-legends.exe. If you delete that folder, the launcher's setup goes with it.

  4. Add it to Steam

    In Steam: Games > Add a Non-Steam Game to My Library > Browse, then choose ultimate-legends.exe. If the .exe isn't listed, set the file type to all files. Then choose Add Selected Programs.

  5. Force GE-Proton for it

    Right-click the new entry and open Properties > Compatibility. Tick Force the use of a specific Steam Play compatibility tool and pick the GE-Proton you installed.

  6. Start it from Steam

    The first start sets up the shortcut's Proton prefix, so give it a moment. Keep using this same shortcut, because your saves live in that prefix: Documents/Activision/X-Men Legends inside its Windows drive, under steamapps/compatdata.

These Steam steps are the standard ones for any Windows program. The tester runs the launcher and the game on the Deck under GE-Proton11-7, but their reports don't spell out the shortcut steps. Our test PC started the same zip with Proton directly (umu), not through a Steam shortcut.

2. Where to keep your games

X-Men Legends II

The PC version isn't on Steam, so the launcher uses a normal install folder: the one with XMen2.exe in it. Copying your installed folder from a Windows PC works. Our test PC ran a copied install under Proton. Installing from the disc through Proton was not tried here.

Example: /home/deck/Games/XML2.

Your disc image

It can go anywhere the Deck can read. The build reads it once. If you keep the build cache (about 3 GB), later rebuilds don't need the image again.

The new game folder

This must be a new or empty folder. As the launcher says, next to X-Men Legends II on the same drive is best. Example: /home/deck/Games/XML1.

Finding them in the file picker

The launcher's file picker is a Windows one, and your Linux files are on drive Z:. For example, /home/deck/Games is Z:\home\deck\Games. SteamOS mounts SD cards under /run/media (Z:\run\media). Games on an SD card were not tested.

3. Choose an update channel

Settings > Updates > Update channel. Stable (the default) gets only full releases. Beta also gets test versions, including the 0.6 online co-op beta.

  • Launcher 0.5.0-beta.3 or later: the list just works. It opens inside the launcher window, so it works under Proton. Use a click, touch, Enter or A to open it, Up / Down to move, and Enter or A to pick. Escape or B closes it without a change.
  • Launcher 0.4.0: the list never appears under Proton. You can still switch blind with the keyboard. Click the box first so it is selected, then press Enter, then Down for Beta (or Up for Stable), then Enter. The change takes effect on the arrow press. Don't press the arrows before the box is selected: they move to other buttons instead.
  • After switching to Beta, update in place. The bar at the top offers the new launcher. Choose Update, then Restart now. In 0.4.0's confirm box, Update is the grey button and the orange one is Not now. The game page updates the XML2 Fix, and Rebuild installs the new builder. On our test PC this worked in place in every direction, with no clean build.
  • Going back to Stable Choose Switch back. It reinstalls the full releases and offers a rebuild. Back up your saves first: a Stable build can't load a save made on a beta build. On our test PC, a save from a 0.5 beta build showed "Save failed".

4. Build and play

  1. Set up X-Men Legends II

    In the library, open X-Men Legends II, choose Set up and then I already have the game installed, and pick its folder. The launcher installs the XML2 Fix there.

  2. Set up X-Men Legends

    Open X-Men Legends, choose Set up, then Choose ISO / XISO. With the Beta launcher you can use Choose extracted XML1 folder instead. Under Where the game goes, pick your new folder, then choose Check XML1 source.

    The launcher downloads the builder. If the download keeps failing, get xml1-builder-<version>-win64.zip from the Legends Classic releases yourself and use Already downloaded the builder? Use its zip.

  3. Build

    On a Windows PC the first build takes 6-8 minutes. Under Proton it takes longer: on our test PC, builds with the disc already cached took 12-18 minutes. We haven't timed a build on the Deck. You can hide the build and keep using the launcher, or cancel it and resume later.

  4. Play

    Press Play on the game page. Starting from the launcher keeps the XML2 Fix in the game folder up to date. The game page's Display rows set the window mode, resolution, frame rate and VSync. The default is borderless at the desktop size.

Optional: a Steam shortcut straight to the game. The builder guide describes adding the built XMen2.exe as its own non-Steam game. If the fix doesn't load, set these Launch Options: WINEDLLOVERRIDES="dinput=n,b" %command%. When the fix loads, xml2-fix.log appears in the game folder. That shortcut gets its own Proton prefix, so it also gets its own saves. The launcher only updates the fix when you start the game from the launcher. These steps were not re-checked for this guide.

Controllers and Steam Input

In the launcher

Every page works with a pad, the keyboard, the mouse or touch. The D-pad or arrow keys move between controls, Enter or A presses, and Escape or B goes back. These come from the launcher's own docs. We haven't checked them with a real Deck pad under Proton.

In the game

The XML2 Fix reads Xbox-style pads. On the Deck, Steam Input always sits between the built-in controls and the game. The tester found that the default bindings were wrong with Steam Input on, and Steam keeps it on for the Deck's own controls. Their workaround was to rebind the controls in the game's options.

After rebinding, the on-screen button prompts can name the wrong buttons. This is a known open issue (XML2 Fix #8). This was reported on the October builds and hasn't been re-checked since.

An external pad

For a pad that isn't the Deck's own, the XML2 Fix's advice is to turn Steam Input off for the shortcut, so the game sees the pad directly. Not tried on a Deck yet.

Gaming Mode

Once the shortcut works in Desktop Mode, it shows up in Gaming Mode under your library's non-Steam games. Start it, move to X-Men Legends with the D-pad, and press Play.

  • Straight into the game (optional) The launcher's -launch xml1 argument, set in the shortcut's Launch Options, starts X-Men Legends as soon as the launcher has loaded. Not tried under Proton yet.
  • Not tested by us Our test PC has no Gaming Mode (gamescope). The tester's reports don't say which mode they played in. If something behaves differently in Gaming Mode, please report it.

Known issues and fixes

  • Black screen at start, before the menu. fixed XML2 Fix 1.8.1 and the 1.9 and 1.10 betas could wait forever while they looked for controllers under Proton. This is fixed in XML2 Fix 1.8.2 (Stable) and 1.11.0-beta.1 (Beta). Update the fix on the game page (pressing Play installs it too). No rebuild is needed. If you're stuck on an older fix, open the game folder's xml2-fix.ini and add these two lines at the end: 
    [Input]
CacheDeviceScan=0
    On our test PC that made the game render, and normal updates and Rebuild kept the line. Do the same in the X-Men Legends II folder if that game goes black too.
  • Drop-down lists never open (update channel, language, display). fixed Fixed in launcher 0.5.0-beta.3 and later. On 0.4.0, use the keyboard steps in step 3.
  • "L_BUILDER_EXTRACT": the builder can't be unpacked. fixed Launchers before 0.2.1 couldn't unpack the builder under Proton. Any current launcher can. If downloading the builder fails, use Already downloaded the builder? Use its zip (see step 4).
  • On Beta, the first build into a new folder stopped after a few minutes. fixed This happened with launcher 0.5.0-beta.2 and older. It is fixed in 0.5.0-beta.3: update the launcher and build again.
  • The launcher window doesn't redraw. open Sometimes the window stops updating. Moving the pointer over it, minimizing and restoring it, or resizing it brings it back. The tester saw this on the Deck, and we saw it once on our test PC after a monitor change. It isn't fixed yet.
  • Wrong bindings or button prompts with Steam Input. open See Controllers and Steam Input.
  • Some graphics may differ under Proton. open In October the tester saw textures turn blocky at some camera angles, and the main menu's Cerebro drawn wrong. We don't know yet whether Proton or the port causes them.

Game issues that aren't specific to Proton are on the main page's Honest limits and in the known issues.

Getting help

Ask on the Discord. Say that you're on a Steam Deck or Linux, which GE-Proton you use and which update channel you're on. Attach xml2-fix.log from the game folder. For a failed build, also attach the build log (on the game page, Open build log). The fix's log can contain your PC's name, local addresses and folder paths.
